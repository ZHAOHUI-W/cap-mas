# P5.5 Frozen OOD Replay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement a frozen, leakage-audited ID/OOD replay evaluator for CAP-MAS that reports paired OOD gaps without changing active policy, memory, skill, cache, or physical execution behavior.

**Architecture:** Add immutable OOD case and split contracts, a fail-closed leakage audit, deterministic confidence/statistics helpers, and a case-scoped runner that reuses `run_online_experiment` and the CAP-X/LIBERO factory. The primary CAP-MAS lane keeps the pre-P5.5 Arbiter behavior; OOD replay is serialized as shadow-only evidence and aggregated against matched ID cases. CAP-X artifacts remain a separate condition adapter and are normalized into the same report format rather than routed through CAP-MAS execution code.

**Tech Stack:** Python 3.12, frozen dataclasses, standard-library JSON/hashlib/math/statistics, existing `Phase5RunDirectory`, CAP-X `.venv-libero`, LIBERO, pytest.

## Global Constraints

- Use the existing CAP-X API and `run_online_experiment`; do not create a second physical execution path.
- Use `CUDA_VISIBLE_DEVICES=5` for real runs unless explicitly overridden.
- Use a fresh output directory for every suite, case, and condition; preserve failed artifacts and logs.
- Do not persist API keys, authorization headers, or provider secrets.
- Keep Memory Bank, Robot Skill Registry, prompts, and Arbiter policy frozen during a suite.
- Do not reuse replay-generated memory or cache state across cases.
- `OODReplayEvidence.shadow_only` is always `True` in P5.5 and cannot change the primary physical winner.
- The first correctness gate uses `max_workers=1` and at most one physical execution per case.
- Do not claim OOD success-rate improvement from cache, latency, or shadow evidence alone.
- No new simulator perturbation generator is included in P5.5; OOD membership comes only from a pre-built, audited manifest.

- [ ] **Step 3: Implement fail-closed audit and dependency-free statistics**

The audit must compare every observed version and cache owner with the frozen
manifest values. It must never infer that an absent value is safe. The Wilson
interval uses the standard normal 95% critical value `1.959963984540054`; the
exact McNemar helper sums the two-sided binomial tail using `math.comb`, so no
SciPy dependency is added. `aggregate_ood_pairs` must preserve `None` results
as infrastructure/unknown records and exclude them from ordinary success
denominators while reporting their count separately.

```python
@dataclass(frozen=True)
class OODRunConfig:
    selection_repeats: int = 1
    max_workers: int = 1
    timeout_s: float = 360.0
    max_restarts: int = 0
    max_steps: int = 32
    gpu: str = "5"
    cache_mode: Literal["disabled", "enabled"] = "disabled"


@dataclass(frozen=True)
class OODCaseResult:
    case_id: str
    pair_id: str
    status: str
    case_dir: Path
    evidence: tuple[OODReplayEvidence, ...]
    primary_winner: str | None
    selection_basis: str | None
    physical_execution_count: int
    error: str | None = None


@dataclass(frozen=True)
class OODSuiteReport:
    suite_dir: Path
    case_results: tuple[OODCaseResult, ...]
    aggregate: OODAggregateReport
    case_count: int
    failed_case_count: int
```

Before the first case, load and validate the candidate artifact digest and run
`assert_leakage_free`. Create a suite `Phase5RunDirectory`, write the frozen
manifest/config, and create one child `Phase5RunDirectory` per case. For each
case, call `load_online_candidates`, `_build_live_executor`, and
`run_online_experiment` with the case's `config_path`, candidate artifact,
seed, object/target names, scene version, and `cache_mode="disabled"`.

Use `mode="online_bounded"`, preserve `provider_call_count`,
`selection_latency_ms`, physical result, winner, selection basis, and
rehearsal records. Convert the result into `OODReplayEvidence` with
`condition="capmas"` and `shadow_only=True`; use `None` for evaluator success
when no physical result or infrastructure completion exists. Never call a
Memory or Skill promotion API. If a case fails, write `failure.json`, partial
results, `logs/runner.log`, and its manifest, then continue unless
`--fail-fast` is set.
